# Evaluation Methods Comparison

## When to Use Each Method

| Method | Best For | Strength | Limitation |
| --- | --- | --- | --- |
| Heuristic evaluation | Early expert review | Fast, structured, low-cost identification of common usability issues | Can miss domain-specific user behaviour |
| Cognitive walkthrough | Learnability and first-time use | Excellent for task clarity and progress feedback | Focuses on specific tasks rather than overall product health |
| Analytics review | Behaviour at scale | Shows where users actually drop off or hesitate | Explains what happened, not always why |
| Inspection checklist | Compliance and quality gates | Good for repeatable review and team handoff | Can become superficial if treated as a box-ticking exercise |
| A/B testing | Comparing live alternatives | Supports data-driven release decisions | Requires enough traffic and a measurable success metric |

## Teaching Framing

- Start with heuristics to surface obvious risks.
- Use a walkthrough to understand why a novice user may struggle.
- Use analytics to validate whether those struggles appear in behaviour.
- Use a checklist to make quality conversations repeatable across reviewers.
- Use A/B testing when you need live evidence between two credible options.
